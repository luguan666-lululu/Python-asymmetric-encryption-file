# v1.1 — 文件与消息加密、顺序检查

新增文本消息加密及页面内解密结果，文件与消息统一在“解密”页自动识别处理。新增发送/接收顺序检查，顺序异常时可选择继续。

文件保持 24 MiB 分块和流水线处理。密文布局调整为四次 KEM 封装、会话秘密摘要双签名及嵌套 AEAD，不再使用 AES-CBC 数据层；更新了使用说明、依赖记录和安全模型。

## 升级注意

v1.1 没有 v1.0 密钥和密文的自动迁移功能。双方应统一版本，重新生成并可信交换公钥；保留旧程序与旧密钥处理历史密文。

输入的是通信对方的名称：`对方名称——私钥` 属于自己，`对方名称——公钥` 属于对方。实际私钥不应发送给别人。

## 已知边界

顺序检查是提醒，不严格阻止重放；崩溃、断电或读写失败可能失步。确认覆盖旧密文后，不保证操作失败时仍能恢复旧文件。

部分随机填充未认证，不保证隐藏精确长度；无前向保密。接收方两套解封装私钥泄漏后，历史密文可被解开，也可能沿用旧会话签名伪造新正文。

本项目未经过独立安全审计。完整运行说明、环境及边界请阅读仓库 README 和 SECURITY.md。附件系统要求与 SHA-256 应以本次实际发布和构建验证结果补充。
